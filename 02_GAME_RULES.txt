# 年会现场三游戏完整规则 V2.1

用途：作为Codex实现三款年会现场游戏的规则依据，与config/game_rules.v2.1.json一致。规则版本onsite-v2.1-candidate。一次活动内短时参与，不采用每日刷新或长期运营机制。

本规则给出可直接实现的确定性初值。三款的满分路径已完成纯数学模拟校验，但这不等于真实手机游戏已经验收；手感、真实难度和三游戏得分分布须由后续可玩样机校准。

## 1. 已冻结的活动规则

- 三款游戏全部交付：羊羊叠高高、羊羊跨栏、赶羊入圈。
- 每个正式局最多45秒；统一30Hz逻辑模拟，共1350个tick。
- 每位参与者全场共3次正式机会，可自由分配到三款；练习不消耗正式机会。
- 一局经服务端验证、正常结束且至少发生一次被游戏接受的有效操作，获得20参与分，加0至80表现分。
- 自然失败也属于正常结束，符合有效操作门槛时仍获得20参与分和已取得的表现分。
- 主动放弃、无效成绩、超过提交截止时间且未完成有效提交，均不获分。
- 45秒游戏倒计时结束是正常完成，不属于“提交超时”。
- 无有效操作而自然结束：记录实际结束原因及NO_VALID_INPUT标志，正式机会已消耗，入账0分；客户端不能把无效按钮连点算成参与。
- 三次已验证局次直接累计，每局最高100，总计最高300；不使用“每日最高分差额发放”。
- 参与分与表现分在核验后一次性入账；有效局次按局号幂等，重试提交不能重复入账。
- start成功占槽并预约3000毫秒后开赛；提交截止为play_started_at后60000毫秒，完整到达时刻等于截止仍可接受；上传宽限不增加45秒游戏时长。槽位、幂等和补偿由01及03定义。

## 2. 公共逻辑约定

### 2.1 坐标与数值

- 逻辑坐标与屏幕像素分开；缩放、不同DPR、斜俯视投影均不能修改逻辑坐标、速度和判定。
- 单位SCALE=1000：1000整数单位表示1个逻辑像素。本文有后缀U的字段使用该整数单位。
- 位置、速度、时间、分数、实体ID和计数均采用整数；不要在游戏逻辑中使用渲染deltaTime、浮点三角函数或随机Math.random。
- 函数truncDiv(a,b)表示向0截断的整数除法，b>0；isqrt(n)为非负整数平方根的向下取整。
- 单位向量：若(dx,dy)=(0,0)，返回(0,0)；否则令d=ceilSqrt(dx²+dy²)，其中ceilSqrt(n)=isqrt(n)+(isqrt(n)²<n ? 1 : 0)，返回(truncDiv(dx×1024,d),truncDiv(dy×1024,d))。小向量也严格按此取整，例如unit(1,1)=(512,512)。separation距离衰减另按第5章使用floor平方根。
- 所有逻辑数值乘积须保持在JavaScript安全整数范围内，服务端与客户端使用同一份模拟核。
- 所有碰撞图形来自规则配置，不从图片透明区域、羊毛、羊角或阴影自动生成。

### 2.2 tick与输入

- 初始状态为tick=0。逻辑tick依次处理1至1350，每tick代表1/30秒。
- 输入事件记录为{tick,seq,type,value}，tick为正整数，seq为整局正整数递增序号、允许不连续；客户端仅能提交输入，不能指定最终位置、成绩或已入圈ID。seq随输入递增时tick不得倒退，所有输入不得超过首次终局tick。
- 客户端将发生于逻辑经过时间elapsedMs的输入归入floor(elapsedMs×30/1000)+1；超过1350的输入不进入本局。
- 同tick按seq升序处理；同seq且内容相同不重复执行，同seq但内容不同拒绝整份提交。同tick相同离散动作最多接受一次；客户端应将同tick多次方向采样合并为最后一条状态后上传；上传仍限制每tick最多1条移动状态，另可1条吠叫。
- 输入在对应状态不合法时忽略，不改变有效操作门槛；格式、事件数量、时间或物理过程异常由服务端核验判无效。
- 资源加载和教程不占槽。正式start成功即占槽并建立SCHEDULED，play_started_at=created_at+3000毫秒；预约期无玩法输入，开赛后才从tick0推进。响应迟到或重试不能更改时轴。
- 正式局不能通过暂停、切后台、刷新或切游戏获取新的45秒。恢复时按原时间和完整输入推进。赶羊DOG_MOVE只作用于本tick，缺省为(0,0)；松手、手势取消、失焦和后台清空控制，缺失时段按无输入推进。练习允许暂停。详细采样、控制凭证和时钟协议见07。

### 2.3 统一同tick顺序

1. 确认局次仍为RUNNING，读取并过滤本tick输入。
2. 应用合法输入，更新动作状态与必要冷却。
3. 推进本tick的位置、速度、计时相位和对象状态。
4. 处理碰撞及目标判定，按实体ID升序处理多个同类事件。
5. 对该tick实际发生且合法的得分事件一次性提交，记录事件ID，禁止重复。
6. 判断结束；同tick优先级为THREE_MISSES（仅叠高高），高于GOAL_REACHED，高于TIME_LIMIT。
7. 若tick=1350且没有更早级别的结束条件，正常TIME_LIMIT。结果冻结，后续输入不得修改。

以上是公共阶段；各款专属顺序必须保持。赶羊将输入与移动阶段明确拆为“读取意图→移动犬→处理BARK→读取羊共同快照并移动全部羊”，不能把BARK提前到犬移动之前。第5.4节为该款唯一顺序，输入seq不改变这个阶段先后。

补充：同tick发生叠高高最后一次失误时，本tick已经满足条件的合法得分仍按规则保留；客户端与服务端不能因视觉动画先后决定是否计分。第1350tick完成目标也先计入该tick得分，再结束。服务端判无效可以最终覆盖正常结束的入账资格，但不能伪造新的游戏分数。

### 2.4 统一计分

```text
if verified && normalEnd && acceptedActionCount >= 1:
    participation = 20
    performance = gamePerformance    // 整数，0..80
    credited = participation + performance
else:
    participation = 0
    credited = 0
```

服务端需由模拟状态重算gamePerformance，不信任客户端自报。仅在验证通过后才能显示“已获得积分”；核验中显示“本局成绩核验中”。主动放弃与已提交核验互斥。

正式逻辑seed全员固定：stack=1，runner=1（赛道不随机），herd=47。seed不是凭证；session_nonce和控制凭证另行管理。

## 3. 羊羊叠高高

### 3.1 玩家看到的玩法

小羊站在完整草垛托盘上，在上方左右移动。看准下方位置点击放下。站稳增加一层，落得准获得完美奖励。小羊与托盘始终完整，不裁掉身体，不把托盘越叠越窄。塔身晃动仅为表现，不引入随机整体倒塌。

### 3.2 精确初值

| 参数 | 值 |
|---|---:|
| 逻辑画面宽度 | 360000 U |
| 参考视窗高度 | 480000 U，镜头可上移 |
| 托盘固定宽度 | 112000 U |
| 每层逻辑高度 | 44000 U |
| 初始顶面中线X | 180000 U |
| 初始顶面Y | 430000 U |
| 上方小羊摆动X范围 | 72000至288000 U |
| 初始速度 | 3000 U/tick |
| 加速公式 | 3000+350×floor(已成功层数/4) U/tick |
| 落下阶段 | 12 ticks |
| 非终局的站稳/失误缓冲 | 6 ticks |
| 最大成功层数 | 20 |
| 最大失误次数 | 3 |
| 成功最低重叠宽度 | 56000 U，即托盘宽的50% |
| 完美最大中线误差 | 6720 U，即托盘宽的6% |

### 3.3 状态与运动

- 状态为READY、FALLING、SETTLING、ENDED。
- 每次生成可操作小羊，按(runSeed XOR attemptOrdinal)的最低位决定起点：0从左端开始、1从右端开始，attemptOrdinal从0递增；初始方向朝内。
- READY时接受一次DROP。接收后固定dropX，不再横移，并设置landingTick=currentTick+12。
- 若本tick未接受DROP，READY对象按速度前进；越过左右边界时做精确镜面反射。等于右边界时方向变为向左；等于左边界时方向变为向右。
- FALLING阶段只等待landingTick；画面下落曲线可以平滑，但不改变逻辑落点或落地tick。
- 到landingTick执行落地判定。成功时增加一层，topCenterX=dropX，topY减少44000 U，托盘宽度仍为112000 U。
- 失败时misses增加1，原topCenterX、topY与成功层数不变。
- 未终局则进入SETTLING，落地tick加6时生成下一只并进入READY；生成当tick不再移动或接收DROP，下一tick开始按READY处理。初始第一只在tick=0已生成，可从tick=1接收操作。
- 相机跟随只影响渲染位置，不影响上述世界坐标。

### 3.4 判定与分数

```text
delta = abs(dropX - topCenterX)
overlap = max(0, 112000 - delta)
success = overlap >= 56000
perfect = success && delta <= 6720
performance = 2 × successCount + 2 × perfectCount
```

- 每成功一层获得2表现分；该层完美再加2。20层全部普通表现40，总积分60；全部完美表现80，总积分100。
- 没有连击额外分、时间奖励或高度额外分，避免超过80。
- 满20层提前GOAL_REACHED；第3次失误提前THREE_MISSES；否则1350tick正常结束。
- 倒计时结束时仍在下落但landingTick尚未到达的小羊不计入层数，也不额外算失误。
- DROP仅在READY被接受时计为有效操作；FALLING、SETTLING、ENDED连点或长按重复不计入。

### 3.5 教程与手感

- 先给一只慢摆羊，提示“看准位置，点一下放下”。演示有效支撑面和完美区。
- 练习完成1次成功即可进入正式模式，不要求先拿满分。
- 前三层摆动速度较低；不增加随机横风、隐藏碰撞或整体倒塌。
- 落地时用挤压、托盘微弹及“叠稳+2”反馈；完美时另显示“完美+2”，本层合计4分。失误用完整小羊弹开或飘走。
- 对runSeed=1，按[37,92,147,202,253,304,355,406,454,502,550,598,644,689,735,780,824,867,911,954]的tick接受DROP，可在第966tick（32.2秒）完成20次完美落地，表现80。此为规则数学向量，证明45秒内存在满分完成路径，不代表触控手感已验收。



## 4. 羊羊跨栏

### 4.1 玩家看到的玩法

小羊自动奔跑，点击跳栏，碰到福草外圈得1表现分，碰到金色核心再得1。固定20栏、10草，整局45秒。碰栏记录一次失误、该栏不给安全通过分；不会提前淘汰，不扣已取得分、不减速，不设生命值或无敌时间。只要有有效起跳并按规则自然结算即可得20参与分及已有表现。

### 4.2 精确初值

| 参数 | 值 |
|---|---:|
| 逻辑可视宽高 | 360000×220000 U |
| 地面Y / 脚部X | 180000 / 88000 U |
| 身体X范围 | [74000,102000] U |
| 身体Y范围 | [feetY-36000,feetY-2000] U |
| 起跳初速 / 重力 | -12500 U/tick / +800 U/tick² |
| 障碍高度 / 顶部Y | 30000 / 150000 U |
| 障碍宽度 | 按passTick所属阶段为8000 / 18000 / 28000 U |
| 收草判定点 | (88000,feetY-19000) U |
| 草中心Y | 69000 U |
| 普通外圈半径 / 精准内圈半径 | 4500 / 1500 U，含相切边界 |
| 起跳预输入 | 本tick及后3tick，共4tick |

### 4.3 固定不等间隔赛道

速度按当前tick：1..450为2400 U/tick，451..900为2800，901..1350为3200。对应72、84、96逻辑像素/秒。

```text
D(t)=2400*min(t,450)+2800*clamp(t-450,0,450)+3200*clamp(t-900,0,450)
passTicks=[180,249,318,359,400,445,518,591,661,703,
           742,785,858,931,1002,1043,1084,1127,1196,1263]
width(i)=8000 if passTick<=450 else 18000 if passTick<=900 else 28000
worldLeft(i)=D(passTick(i))+74000-width(i)
screenLeft(i,t)=worldLeft(i)-D(t)
```

障碍ID1..20按表顺序。宽度按本栏passTick固定，不随它运行经过速度分界而改变；三段分别6、7、7栏。安全通过基准首栏6秒、末栏42.1秒，间隔39至73tick。固定但不等间隔，所有正式玩家使用同表；不随机难度或凭关卡生成器另排障碍。玩家用画面判断，无需背拍。

10草绑定偶数障碍，grassId=obstacleId/2；世界中心X=worldLeft+width/2，Y=69000，画面X=worldCenterX-D(t)。详细坐标及逐草窗口已存唯一JSON。runSeed仅可影响独立装饰流。

### 4.4 跳跃与输入

每tick最多一条JUMP；仅真实按下/点击形成离散动作，键盘自动repeat不形成连跳。JUMP设置pendingJumpUntil=currentTick+3，空中只写缓冲。每tick移动前，如果落地且缓冲有效，设置vy=-12500、清空缓冲并增加acceptedActionCount。实际启动起跳才算有效操作。

腾空时先vy+=800，再feetY+=vy；feetY>=180000夹回地面、vy=0、落地。第15tick附近脚部最高为88500 U，一次起落31tick。落地后有效缓冲在下一tick才重新起跳，不在同tick推进两次。缓冲过期、菜单点击、结束后点击均不增加有效操作。

### 4.5 碰撞、双圈收草与通过

1. 推进羊的跳跃、赛道位移和对象位置。
2. 按障碍ID检查身体与障碍AABB严格两轴重叠；边缘相切不碰撞。第一次触碰设touched=true、mistakes加1，同栏后续接触不重复记。受挫闪烁仅视觉，不能让别的障碍免碰撞。
3. 按草ID计算收草点到草心的整数平方距离。distance²<=4500²且outer=false时outer=true、普通草次数加1；distance²<=1500²且inner=false时inner=true、精准次数加1。内圈天然包含外圈；同tick可同时得到两分，每个标记最多一次。
4. 外圈已拿后仍继续检测同草内圈，直到草心X<88000-4500，此后不可能再接触。外圈已拿时以弱化草叶+亮金芯提示仍可取精准；不能立即销毁整个草对象，使下一tick内圈奖励丢失。判定只看几何，不另藏“在某起跳tick才算”的条件。
5. 障碍右缘<=74000且未passed时标passed；仅touched=false者safePassedCount加1。碰过的栏永远不给安全通过分。
6. 提交本tick唯一得分事件，再判断终局。所有同类事件按ID升序，规则与动画播放顺序无关。

圈形收草与矩形撞栏边界不同，不能混用。草分与栏分分别由实际几何事件决定，不因本栏失误抹掉已合法取得草分，也不能补发未碰到的草。

### 4.6 分数与结束

```text
performance=3*safePassedCount+outerCollectedCount+innerCollectedCount
0<=safePassedCount<=20
0<=innerCollectedCount<=outerCollectedCount<=10
mistakes=已触碰的不同障碍数，0..20
```

上限60+10+10=80。无距离、存活、连击或额外惩罚。第1350tick自然TIME_LIMIT；跨栏没有其他自然提前终局。已通过全部栏仍跑到45秒。协议拒绝提前自报45秒结束；主动放弃/系统中止由共用流程另行处理。

例：6安全栏、1份外圈且该草精准→20表现，总40；20栏全安全无草→60表现，总80；所有栏与双圈全得→80表现，总100。没有实际起跳即使到时仍入账0。

### 4.7 黄金向量与窗口

```text
JUMP ticks=[159,227,297,337,379,423,496,569,639,681,
            720,763,836,908,979,1020,1061,1104,1173,1240]
```

该路径1350tick结算：20安全栏、0失误、10外圈、10内圈，表现80，总100。逐栏安全起跳离散窗口按三段为12/10/9个tick；各草外圈窗口8/8/7个tick，内圈均3个tick。非空内圈严格包含于外圈、外圈严格包含于安全窗口。这里计数乘1/30秒表示离散槽数，不等同连续首尾时刻间距。

这证明合法满分路径和精确奖励可达，不代表手机上人人能做到。每tick连点的参考结果为47积分，不是满分；本次固定节拍搜索也不能证明所有脚本均被防住。详见06合成方法与真人校准门槛。

### 4.8 教程与可读性

10至15秒教程先演示接近木栏点击，再展示草叶+1、金芯再+1；“碰栏继续”明确告诉玩家。游戏区与大按钮均可点，HUD/返回/静音阻止事件穿透。前方可见距离、较细的首段栏与草心对比度须在真机检查；图形可加描边，逻辑碰撞仍按配置。羊角、毛边与影子不计撞栏。

## 5. 赶羊入圈（V2.1 冻结候选）

本章是赶羊游戏的完整逻辑定义；规则版本 onsite-v2.1-candidate。已完成确定性参考模拟和一条满分输入重放，尚未完成真人触控、难度分布和设备性能验收。参数在本轮后冻结，真人试玩是活动上线闸门。

### 5.1 玩法、时长与正式种子

玩家移动牧羊犬，绕到小羊后方，把8只羊赶过围栏入口；吠叫可短时扩大驱赶半径。单局最多45秒，30Hz，共1350个逻辑tick。初始状态为tick=0，依次处理tick=1..1350。8只全部入圈立即结束，否则第1350tick正常结束。

本活动所有人的所有正式赶羊局使用同一非零32位种子47，同一初始位置、墙体和参数。练习默认也使用47。种子只决定逻辑wander方向，不作为反作弊凭证或秘密；客户端必须使用服务端下发的本局规则版本与固定种子。防重放、参与者身份、票据、提交时限由共用后台执行。

审查时使用的其他seed是synthetic压力测试条件，不作为给不同正式参与者分配不同随机难度的机制。若以后更换种子或参数，必须形成新规则版本并重新验收；活动中途不得静默修改。

### 5.2 整数、单位向量与输入归一化

坐标使用整数U，1000 U=1逻辑像素；X向右为正，Y向下为正。斜俯视投影、DPR、屏幕大小、图片大小只影响渲染。

本章的unit1024必须使用向上整数平方根，覆盖旧版赶羊中以floor平方根归一化的写法。其他游戏的数值约定不由本章改变。

```text
truncDiv(a,b): 对a/b向0截断，b>0
isqrt(n): 非负整数平方根向下取整
ceilSqrt(n):
    d = isqrt(n)
    return d+1 if d*d<n else d

unit1024(dx,dy):
    if dx==0 and dy==0: return (0,0)
    d = ceilSqrt(dx*dx+dy*dy)
    return (truncDiv(dx*1024,d), truncDiv(dy*1024,d))
```

由此unit1024输出满足ux²+uy²≤1024²。量化会使某些小向量明显减速，这是冻结规则，不能再补一个浮点归一化。例如unit1024(1,1)=(512,512)，不是(1024,1024)。所有平方、乘积和求和保持在JavaScript安全整数范围；JS与服务端必须共享同一个整数模拟核，不能分别以浮点近似。

DOG_MOVE的value是{x,y}，每分量是[-1000,1000]范围内整数，布尔值、NaN、浮点、小数和越界分量都不是合法格式。先验证分量，再执行：

```text
n = x*x+y*y
if n>1000000:
    d = ceilSqrt(n)
    x = truncDiv(x*1000,d)
    y = truncDiv(y*1000,d)
move = (x,y)
dogDx = truncDiv(x*3200,1000)
dogDy = truncDiv(y*3200,1000)
```

归一后move模长≤1000，期望位移模长≤3200 U/tick；正常碰撞和边界截断后实际位移也不得超过3200。不能按X/Y分别给3200后允许斜向超速。例：(1000,1000)归一为(706,706)，每轴位移2259 U；(1,1000)归一为(0,999)。

每tick最多上传一条DOG_MOVE和一条BARK。客户端应把同tick多次摇杆采样合并为最后一条后上传。这个tick缺少DOG_MOVE时，方向必须为(0,0)，不得沿用上一tick状态；松手可明确上传(0,0)。键盘WASD/方向键先生成分量-1000/0/1000，再使用同一归一化；空格对应BARK。

输入事件仍使用{tick,seq,type,value}；seq为全局递增正整数、可有间隔，完全相同seq与payload重试去重，冲突重复拒绝。BARK的value为null。同tick事件先按seq读取，但逻辑阶段固定为先移动狗、后触发吠叫，不因这两条输入的seq先后而改变空间判断。tick=0及结束后的输入不进入模拟。

### 5.4 每tick固定执行顺序与有效操作

1. 确认局次RUNNING，过滤本tick输入。没有DOG_MOVE即(0,0)；没有BARK即不请求吠叫。
2. 按第5.2节归一化移动输入；犬执行X后Y扫掠及边界夹取。实际位置发生非零变化，acceptedMoves才加1；即使摇杆非零，完全被边界挡住也不计有效移动。
3. 使用犬本tick已解析的位置处理BARK。若有请求且tick≥nextBarkTick，触发：barkActiveUntil=tick+12、nextBarkTick=tick+150。若触发时至少一只尚未入圈羊与犬的平方距离≤126000²，acceptedBarks加1；判定使用羊本tick移动前的快照。
4. 空吠仍扩大影响半径并消耗冷却，但不增加acceptedBarks；冷却期间的请求直接忽略，既不触发也不延长冷却。不能把之后才进入扩展范围的羊追溯计为触发时的有效吠叫。
5. 在tick<barkActiveUntil期间影响半径为126000，否则84000。按固定tick刷新wander；读取所有未入圈羊的同一份旧位置快照。
6. 为所有未入圈羊计算普通向量与受驱赶状态，再按“墙面辅助>旧侧移>普通运动”的优先级确定期望位移，执行相同扫掠。不得用前一只已更新的位置影响后一只。
7. 同时应用全部新位置；按羊ID升序判定入圈，生成唯一计分事件并锁定该羊。
8. 提交本tick合法计分，再判定结束。8羊全齐优先GOAL_REACHED；否则tick=1350为TIME_LIMIT。本tick最后一羊入圈仍先计分再结束，不能重复结算。

acceptedActionCount=acceptedMoves+acceptedBarks。完整自然结束、服务端核验通过且该值≥1，才符合20参与分资格；主动放弃、无效成绩或超过提交截止未完成有效提交为0入账。无操作自然结束也消耗正式机会，记录NO_VALID_INPUT，入账0；不要把它自动当作弊。提交时限与网络处理仍按全平台规定，不能延长45秒逻辑时钟。

### 5.5 羊的确定性普通运动

所有空间半径比较使用平方距离，避免比较时另用浮点sqrt。所有邻居均排除自身和已入圈羊。以下向量均以1024缩放。

1. flee：unit1024(羊中心-犬本tick已移动中心)。狗羊完全重合时使用固定方向表[(sheepId-1)%8]，因此ID1对应索引0。
2. cohesion：取平方距离≤110000²的其他羊；每轴先truncDiv(该轴坐标和,邻居数)求整数平均，再从本羊指向平均点取unit1024。无邻居时为(0,0)。
3. separation：对平方距离<30000²的邻居，令distance=isqrt(dx²+dy²)，away=unit1024(本羊-邻居)。每只邻居的每轴先计算truncDiv(awayAxis×(30000-distance),30000)，然后累加这些已舍入的贡献，最后对总和取unit1024。不能先累加分子再统一除法。若两羊中心重合，away=(0,0)，此邻居贡献为0；不另加未定义随机推开。
4. gate：unit1024(180000-x,60000-y)。
5. wander：固定八方向表中的一个向量，按第5.8节刷新。

八方向表索引0..7为：

```text
[(1024,0),(724,724),(0,1024),(-724,724),
 (-1024,0),(-724,-724),(0,-1024),(724,-724)]
```

若羊与犬平方距离≤当前影响半径²，称为受驱赶：

```text
desired = unit1024(8*flee + 4*cohesion + 6*separation + 5*gate)
speed = 2000
```

否则：

```text
desired = unit1024(2*cohesion + 6*separation + wander)
speed = 300
```

普通期望位移为(truncDiv(desired.x*speed,1024),truncDiv(desired.y*speed,1024))，模长不超过speed。零向量产生零位移。犬位置使用本tick已移动后的值，羊邻居位置始终使用共同旧快照。

不加未定义的加速度、浮点归一化、概率惊跑或刚体碰撞。羊之间采用上述soft separation；若未来真人样机需要另加位置投影，须另起规则版本。

### 5.6 围栏与扫掠

实际围栏是两条水平线段：[(0,76000),(144000,76000)]、[(216000,76000),(360000,76000)]。按羊半径做保守AABB膨胀后，羊中心不能进入以下矩形内部：

```text
leftWall  = {minX:-10000,maxX:154000,minY:66000,maxY:86000}
rightWall = {minX:206000,maxX:370000,minY:66000,maxY:86000}
```

这是确定性的保守矩形处理，边角较精确圆角略紧。严格进入内部才碰撞，相切允许；x=154000或206000可沿入口边缘移动。犬使用整条关闭围栏膨胀矩形[-9000,369000]×[67000,85000]，不能进羊圈。

每tick先扫掠X，再用解析后的X扫掠Y，最后分别应用外边界：

```text
sweepAxis(pos,delta,fixedOther,walls,axis):
    target = pos+delta
    if delta==0: return pos
    for wall in stable wall-ID order:
        lo,hi = wall bounds on this axis
        otherLo,otherHi = wall bounds on the other axis
        if not (otherLo<fixedOther<otherHi): continue
        if delta>0 and pos<=lo and target>lo:
            target=min(target,lo)
        if delta<0 and pos>=hi and target<hi:
            target=max(target,hi)
    return target

newX=clamp(sweepAxis(oldX,dx,oldY,walls,X),minWorldX,maxWorldX)
newY=clamp(sweepAxis(oldY,dy,newX,walls,Y),minWorldY,maxWorldY)
```

禁止只检查移动终点是否在墙内；初始/恢复逻辑快照也不得位于墙内部。出现这种非法状态应判实现或核验异常，不得传送到羊圈。相切时允许沿边滑动，不做随机反弹。

### 5.7 墙面辅助及旧卡住处理

#### 5.7.1 墙面辅助WALL_GUIDE

此辅助解决“羊沿围栏来回移动，实际仍超过150 U，旧stuck判据永远不触发”的情况。它仍需要犬持续施加影响，不会不受驱赶自动完成。

未处于WALL_GUIDE时，在本tick期望位移和扫掠结果得到后，用以下全部条件累计fenceContactTicks：

```text
pressured == true
desiredDy < 0
resolvedY > oldY+desiredDy
resolvedY == 86000
resolvedX not in [154000,206000]
```

本tick满足则加1，否则清零；即使沿墙横向移动超过150 U也累计。达到6tick时，本tick仍保留刚完成的普通扫掠结果，设置wallGuideActive=true，清零stuckTicks与sidestepRemaining；从下一tick开始辅助，不在触发tick重复移动。

辅助期间每tick开始先检查：若已不受驱赶，或当前中心X已在[154000,206000]，退出辅助，清零fenceContactTicks，本tick可按普通运动继续。否则，期望位移为朝入口中心X=180000的水平1000 U，竖直0，仍执行第5.6节扫掠和外边界。辅助中不运行旧侧移，也不累计旧stuck。

辅助的本次水平移动使新X进入[154000,206000]时，移动后退出并清零接触计数；本tick不追加第二次普通移动，下一tick恢复普通运动。辅助本身不产生入圈数、不得穿墙、不得瞬移；仍须中心Y≤66000才能计入圈。

#### 5.7.2 其他位置保留旧侧移

不在墙面辅助、也不在侧移期间时，若受驱赶且实际位移平方≤150²，则stuckTicks加1，否则清零。达到30tick，本tick保留已完成的普通移动，从下一tick开始连续15tick侧移。

侧移方向在触发tick按该羊旧快照X一次确定：X<180000向右，X>180000向左，X=180000则奇数ID向左、偶数ID向右；整个15tick保持此方向。每tick水平1000 U、竖直0，同样扫掠。即使侧移期间不再受驱赶，也完成这15tick；结束清零stuckTicks，下一tick恢复普通运动。

优先级始终是WALL_GUIDE>旧侧移>普通运动；墙面辅助触发会取消旧stuck/侧移状态。已入圈羊不运行任何这些状态。

### 5.8 固定随机流

逻辑随机只用于wander。每局以47初始化xorshift32，操作按32位无符号语义执行：

```text
state ^= state << 13
state ^= state >>> 17
state ^= state << 5
state = state >>> 0
directionIndex = state & 7
```

首次tick=1，之后tick=61、121……刷新。每次按ID1..8各消耗一次，包含已入圈羊；已入圈羊仅消耗不使用，保证随机流不因先后入圈而改变。美术随机使用另一独立流。通用调试若传0，映射到0x6D2B79F5；正式局不接受客户端把47换成0或其他种子。

seed47的首8次无符号输出应为：

```text
[12182925,3171101353,3533354690,202647683,
 2844101665,406168577,974100795,3963299919]
对应方向索引：[5,1,2,3,1,1,3,7]
```

### 5.9 入圈、计分与结束

羊中心X∈[154000,206000]且Y≤66000时标记inPen=true。按羊ID记录一次入圈事件与tick，锁定后移出主动模拟，不再受犬影响、出圈或阻挡其他羊。可以在纯渲染层继续走进展示位置；展示动画不改变逻辑位置或得分。

```text
basePerformance = 6 * inPenCount
if inPenCount==8:
    timeBonus = clamp(floor((1200-finalTick)/30),0,32)
else:
    timeBonus = 0
performance = basePerformance + timeBonus       // 0..80

if verified && normalEnd && acceptedActionCount>=1:
    credited = 20 + performance                 // 20..100
else:
    credited = 0
```

floor是数学向下取整；实现也可先判断finalTick≥1200令bonus=0，以避免负数除法语义混用。8秒内（finalTick≤240）赶齐满32奖励；超过8秒即开始扣整秒档位。这里参考tick=1200对应40秒，不是修改游戏时长：比赛仍最多45秒。

### 5.12 教程、体验与上线闸门

独立教程只放3只羊，明确演示“绕到后方”“跟着羊移动”“靠近围栏时继续从后方驱赶”和一次有效吠叫。正式犬速可快于羊，满幅直上容易跑到羊前方；教程必须显示犬位于羊前方时应绕回，不能只提示一直向上。

入口、犬影响圈、摇杆、吠叫冷却、入圈数量、+6表现反馈均可静音理解。未核验时不得把20参与分写成已经到账。停止操作必须停止犬移动；切后台不暂停正式逻辑时钟。

本轮不再调参。上线前用同一批真实参与者试玩三游戏，观察规则理解、低分比例、完成率、满分比例、同分密度、围栏长时间往返和触控失误；验收阈值及全平台排行规则按正式上线清单执行。未通过真人门槛不得仅凭黄金路径或synthetic分布宣称“难度已适中、排行已公平”。

## 10. 正式校准与规则冻结

三款上限一样不代表同样难。06规定真人采样和分布门槛；本版合成实验用于找结构问题，不能代替真人。先完成三款可玩样机，在相同说明与练习条件下进行同人配对；分开看首局/复玩和新手表现，比较同款三次/三款各一次的积分机会。未达标则修改离线候选版本、复测和更新所有文件，不能活动中途按人调难度、追溯改分档或强制每款一次来掩盖问题。

官方seed固定后同款起点一致；练习不计分。允许玩家熟练提升，但需用06限制过低和满分集中。正式发布同时冻结配置、模拟核与资产版本；在途局仍使用原版本核验。
