## Rebuild from the repository root in PowerShell

```powershell
& '.local/tools/blender-4.5.9-windows-x64/blender.exe' -b --python art-source/render_assets.py -- --preview
& '.local/tools/blender-4.5.9-windows-x64/blender.exe' -b --python art-source/render_assets.py -- --all
& '.local/tools/blender-4.5.9-windows-x64/blender.exe' -b --python art-source/render_hero.py
python art-source/build_ui_states.py
python art-source/package_assets.py

python design/source/validate_asset_foundation.py
```

`--preview` renders the first idle frame of each direction plus farm and effects; it does not fulfill the full frame list. `--all` writes 254 character frames, 22 farm-view frames and 5 effects. Frame source remains 512×512; `package_assets.py` retains fixed-crop 256×256 originals under `frames/`, then downsamples to 128×128 and packs the six pages. The sheep/dog original mother files retain stable named collection/object-controller structure and fake-user actions named `actor_camera__clip__controller`; assign the matching actions to their controllers together, timeline frames 1 through clip frame count. The render script is also an executable binding/pose definition. There is no root translation and no gameplay code in the source.

## Integration

- Runtime manifest `/assets/asset-manifest.v1.json`; each entry contains an explicit `runtime_path`. Package-relative baseline `path` remains provenance, not the URL.
- Character atlases `/assets/characters/{sheep_side_v1,sheep_iso8_v1,dog_iso8_v1}.{png,atlas.json}`.
- Atlas `frames[key].rect` is **array [x,y,w,h]**. `pivot_px` is [64,112] side, [64,98] iso; source crops/cameras exactly follow the frozen specification. Extrusion 2 px plus transparent separator 2 px; trim/rotate false; straight RGBA, no baked character shadow.
- Animations use keys `idle.e`, `run.e`, `takeoff.e`, `air.e`, `land.e`, `walk.n`, `bark.n`, etc. There is no `jump` alias: select takeoff/air/land from core state. Never trigger logic from animation completion.
- Environment frames: `hay_tray`, `fence_segment`, `hurdle`, `clover_outer`, `clover_core`, `grass_tile`, `dirt_tile`, `barn`, `gate_marker`, `flower`, `shadow_contact`. The gate marker has an explicit open arrow; don't scale fence art into the defined sheep-center channel. Outer clover and gold core remain independent.
- Effects frames: sparkle, dust, bark_wave, entry_ring, confetti. All text feedback stays in live DOM. Reduced motion may show static icons. Optional original synthesized WAV cues are separate from visual feedback and may be muted.
- UI copied from editable SVGs; `design/ui_kit/button-states.json` defines normal/pressed/focus/disabled/loading. Labels/numbers remain real components, minimum target 48 CSS px, and disabled reasons remain readable. Inline instances require an ID prefix.
- Existing placeholder IDs remain marked `placeholder` in the baseline; new atlases use stable production IDs. Loader fallback may use a matching source pivot during local graybox work, but production preflight must fail clearly if candidates aren't available rather than silently treating placeholders as final.

## Review artifacts and limits

Open `previews/atlas_preview.html` to play every direction with a fixed ground cross. `*_contact.png` shows every actual frame. `atlas-validation.json` records exact frame counts, dimensions, source safety margins, animation membership, bounds, page memory, bytes and hashes. Character source `.blend` files include both character collections for easy shared-material inspection, with the unrelated actor hidden.

Automated geometry/packing checks do not certify adult aesthetic preference, motion smoothness on a physical phone, low-memory texture behavior, browser 30/60fps equivalence or actual gameplay integration. No real-device test is claimed here. A final visual review may refine the procedural tufts/horns or material softness; rerender all directions together after any model change.
