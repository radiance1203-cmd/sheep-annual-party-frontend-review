## 2. 已锁定的视觉语言

角色是奶白色软玩具羊：大而清楚的云团绒块、暖米色脸、小黑豆眼、短弯角、棕色小蹄、朱红围巾及一只金铃。前后朝向应由头、蹄、尾和围巾结构表达；背面不补画“朝向镜头”的脸或胸前金铃。牧羊犬用明显不同的棕白配色、长耳和长体型，不与羊混淆。

场景为浅绿牧场、奶黄色土路、珊瑚橙农舍、蜂蜜色栅栏和草垛。界面为奶油色面板、朱红主操作、深棕文字，保留温暖的年会感。不要把儿童教育游戏的高饱和描边、过密贴纸或夸张哭脸引入此基底。背景细节弱于角色与障碍；游戏过程中减少漂浮装饰遮挡。

`design/reference_user.png` 仅供理解软 3D、斜俯视、牧场材质，截图中的第三方角色、Logo、按钮或视频界面不得提取复用。它展示的点羊解堵机制不改变本项目《赶羊入圈》的规则。

四张 `design/prototypes/*.png` 锁定各页气氛、功能层级和示例布局；`design/character_foundation_board.png` 进一步锁定脸型、绒块、角、围巾和金铃。外观板下排两个斜向姿态不是精确 NE／SW，相机和方向必须依照规格重新生成。不要裁切外观板或原型充当透明角色动画。

## 4. 开发接入顺序

1. T-012：读取 tokens、清单、相机／动画及图集规范，建立真实按钮、HUD、对话框与可点击区域；先使用交付的 SVG。
2. T-050：按 `BLENDER_MASTER_SOURCE_TASK.md` 制作羊、狗、农场母源。该任务尚未完成。
3. T-051：由母源离线渲染并装配正式图集，保留同一 `asset_id` 接口、相机、逻辑锚点与动画名；状态通过验收后由 `planned`／`placeholder` 改为生产状态。
4. T-052：前端将经核准的资源集成到 `apps/web/public/assets/`，加载清单并绑定规则状态，不把原型中的示例数字写进组件。
5. T-066／T-067：真机视觉、操作与可读性检查；归档来源、授权和生成记录。真人难度测试可先用占位素材进行，不等正式美术完成。

未来仓库建议由美术持有 `art-source/` 可编辑母源、`assets/` 生产资源，前端负责运行目录集成；这些目录是开发阶段约定，本基底清单不声称它们已存在。现存交付的精确路径一律以 manifest 为准。

## 5. 必须保持的 UI 与规则边界

基准视口 390×844 CSS px，支持窄屏和安全区；正文 16 CSS px 起，分数／时间至少 24 CSS px，最小点击目标 48×48 CSS px。底部操作带为真实组件，摇杆、跳跃和投放按钮无需依靠音效才能理解。允许用户静音，减少动态效果时保留清晰的静态状态反馈。

原型示例 HUD：叠高高 `24/80`（8 层、4 完美：8×2+4×2），跨栏 `20/80`（6 安全越障、1 福草外圈和 1 金芯：6×3+1+1），赶羊 `24/80`（4/8×6）。这些只是展示样例，生产数字从逻辑状态读取。跨栏显示“失误”，没有生命值或红心；叠高高提示“叠稳 +2，完美再 +2”。

30Hz 固定逻辑先确定位置、成功、碰撞、得分和结束，再通知表现层。渲染帧率、动画播放速度、图片尺寸、透明像素或阴影不能改变逻辑判定。跳跃图集不提供物理轨迹；羊和狗的动画不驱动位移；入圈动画不触发第二次计分。

## 6. 规格与验证入口

- `design/design-tokens.json`：颜色、排版、间距、布局、交互和示例 HUD。
- `design/asset_specs/CAMERAS_AND_ANIMATION.md`：方向表、相机、固定画布、pivot、动作帧数与 fps。
- `design/asset_specs/ATLAS_CONTRACT.md`：命名、装配元数据、尺寸和内存／下载预算。
- `design/asset_specs/BLENDER_MASTER_SOURCE_TASK.md`：可编辑母源制作和离线导出任务。
- `design/asset_specs/ACCEPTANCE.md`：占位与正式资产分阶段验收。
- `design/asset_specs/SOURCE_REGISTER.md`：用户参考、生成概念、原创 SVG 和待制作资产的来源记录。
- `design/source/validate_asset_foundation.py`：以包内相对路径验证 manifest、JSON、SVG XML 与声明尺寸；不声称游戏已通过真人测试。

本文件和 SVG 能让 Codex 立即搭建正确界面与资源接口。最终绒羊材质、完整八方向、动画流畅度、正式场景和真机性能仍须按上述任务完成，不能因占位图已经显示就标记美术完成。
