# 羊年年会现场游戏平台 PRD

文档交付版本：V2.2。规则版本：`onsite-v2.1-candidate`。本 PRD 整理产品与开发边界，保持 V2.1 的玩法、种子和积分；补场阶段采用本交付 V2.2 的明确化：未封榜 PLAYING / DRAINING 均可发放并使用指定原槽授权，普通开局不能占用该保留槽。正式游戏种子固定为 `stack=1 / runner=1 / herd=47`。当前交付是需求、方案、视觉方向和数学参考；尚无生产系统、真实手机或真人难度验收通过的声明。

## 1. 产品目标与范围

为一次公司年会提供三款可自由选择的短局 H5 游戏：羊羊叠高高、羊羊跨栏、赶羊入圈。三款全部交付，共用身份、整场三个计分槽、积分流水、荣誉榜、礼品池、领取核销和主办方后台。参与者在主持人安排的暖场窗口内完成少量游戏，以积分兑换礼物，不需要一直看手机。

本期目标是让第一次接触的同事看懂玩法、完成参与，并让更准确的操作获得可解释的表现分；不能仅凭三款同为 100 分就声称难度相同。用户的现有羊形象参考及四张原型确定视觉方向；同一个角色母源输出不同视角，三个游戏复用公共美术与 UI。

### 1.2 默认现场规格

| 项目 | 本版规格 |
|---|---|
| 活动单元 | 一次 `event_id`；真实公司、日期、人数、名单、奖品由主办方配置 |
| 入口 | 公共活动二维码 + 名单内个人随机邀请码/个人二维码，或已经具备的企业身份接口 |
| 阶段 | CHECK_IN → PLAYING → DRAINING → REDEEMING → CLOSED |
| 挑战准入窗口 | 建议 20 分钟，可预先配置；不是要求连续游玩 20 分钟 |
| 正式机会 | 每人整场固定槽 1、2、3；三款任选，可重复同款，不跨日重置 |
| 练习 | CHECK_IN / PLAYING 且入口开关允许时可开始；不占槽、不发正式积分；不限制次数 |
| 单局 | 成功预约即占槽；服务器统一预约 3 秒后开赛；玩法最长 45 秒 |
| 提交 | 自正式开赛起 60 秒内完整到达，最后 15 秒只作上传宽限；创建到截止最长 63 秒 |
| 积分 | 有效自然终局并核验通过：20 参与 + 0–80 表现；三槽累计最多 300 |
| 荣誉榜 | 有效累计分降序，同分并列 1、2、2、4；消费不降荣誉分 |
| 兑礼 | 复核封榜后开放；统一库存，默认每人一件；先扣分预留，领取时核销 |
| 移动端 | 390×844 CSS px 设计视口，安全区适配；主要触区至少 48×48 CSS px |
| 大屏 | 独立 16:9 只读布局，显示公共信息与掩码榜单 |
| 初始容量验证假设 | 300 人名单、150 人同时游玩、100 份终局在 5 秒内到达，并有新预约与轮询 |

容量数字是待测负载基线，不是实际员工人数或已验证承诺。三局最长玩法共 135 秒；预约、教程、等待与结算另计。主持人可在主要节目开始前关闭新开局。

## 2. 用户与权限

| 角色 | 能做的事 | 不能做的事 |
|---|---|---|
| 未绑定访客 | 查看公开活动说明、阶段和登录入口 | 正式预约、查询任何人的局次/钱包/凭证 |
| PARTICIPANT 参与者 | 查看自己的资格、三槽、局次、余额、订单；选择游戏；原控制端提交/放弃；兑礼及取消自己的未领取订单 | 操作他人或其他活动对象、核销、控阶段、改库存/分数/槽数 |
| REDEEMER 核销员 | 在授权活动内查询领取必要信息、核销符合条件的订单、查回原核销记录 | 改阶段/库存/积分、补场、全量名单导出 |
| ORGANIZER 主办方 | 配置本活动、导入名单、发放/恢复身份、控制阶段、复核、更正、原槽补场、礼品库存、核销及导出 | 跳过截止/封榜关口、给第四槽、直接改余额伪造结算 |
| 现场大屏 | 只读公开阶段、公共二维码、参与概况、掩码荣誉榜 | 展示邀请码、控制凭证、手机号、个人核销码或后台操作入口 |

主持人可由主办方授权人员操作控制台，不另外增加一个绕开服务端权限的角色。开发测试身份只存在于显式开发环境，不自动进入正式名单。

所有写操作和敏感查询都在服务端检查会话、角色、event 和对象 owner；隐藏按钮不算权限控制。登录随机码、运行控制 secret、核销凭证三者分离，日志脱敏。个人码一人一份；公共二维码不直接赋予额度。恢复身份回到原参与者及原三槽，并撤销旧会话/控制权。

## 3. 完整参与路径

### 3.1 正常路径

1. 主办方填入真实配置，导入名单并发放个人码；工作人员在隔离开发/演练活动中预演。
2. 参与者扫公共码进入，绑定自己的个人码，确认活动规则、身份和剩余机会。
3. 在大厅任选一款，查看 10–15 秒可跳过教程并练习；练习与正式机会清晰区分。
4. 正式开始前完成资源、版本、持久化与时间预检。按钮明确“使用 1 次机会”；失败预检不占槽。
5. 成功预约占用服务器决定的空槽，显示实际剩余的 3 秒预约倒数。到服务端开赛时间后进入玩法。
6. 游戏自然结束后封存完整输入，同一个 body 自动重传；分清待同步、核验中、待复核和已到账。核验通过才显示参与分、表现分及正式积分。
7. 已封存核验中可选下一空槽；仍在预约/运行/待上传时不可另开一局。全部三槽用完后仍可看记录与榜单。
8. 主持人收尾，处理所有在途、入口受理、任务、复核与补场授权，封榜后开放礼品。
9. 用户按实际余额和公开积分价选择一件礼品，下单扣分并预留；出示订单凭证。
10. 核销员确认服务器核销成功后交付实物。活动结束后，已有订单仍可在已公布领取截止前领取或取消；新下单关闭。

### 3.2 弱网和异常路径

| 场景 | 用户路径与结果 |
|---|---|
| 开局响应未知 | 保留原 start 键与控制凭证，重试/查询原局；不生成新键重复扣槽 |
| 响应迟到或刷新 | 按原服务端时轴与完整日志恢复，不重新倒数 3 秒或获得 45 秒 |
| 后台、失焦、手势取消 | 清空控制；正式逻辑按原时间零输入推进，不暂停、不用新手势回填过去 |
| 自然失败 | 至少一个被接受操作且其他条件成立时仍有 20 参与分及已取得表现分 |
| 零操作、主动放弃、首次提交超时 | 0 分，槽已使用；分别显示实际原因，零操作不自动标作弊 |
| 上传中断 | 封存同一 body 并在原截止内重传；准时已受理的过程可在截止后查询核验 |
| 本地日志无法恢复 | 说明原因并保留实际局号，不凭客户端分数补造过程；按原因结案或申请工作人员复核 |
| 系统故障补场 | 工作人员核对证据，作废旧尝试并全额冲正，将指定原槽保留给单次授权；重赛按新实际分，不保留旧高分 |
| 多设备 | 其他设备可读本人当前状态；无原控制权不可提交/放弃原局。身份恢复撤销旧控制权 |
| 积分/资格待复核 | 不预支待核验分；需要时同时冻结新兑礼和旧待领取凭证 |
| 核销响应丢失 | 查询原订单和原核销记录；已核销不重新交物，不把重试做成第二次发奖 |

## 4. 三款玩法与统一计分

| 游戏 | 操作与目标 | 表现分 | 自然结束 |
|---|---|---|---|
| 羊羊叠高高 | 看准位置点击放羊；完整固定托盘，不裁羊、不越叠越窄 | `2×成功层 + 2×完美层`；完美误差 ≤6720 U，50% 支撑即成功 | 20 层、3 次失误或 45 秒到点 |
| 羊羊跨栏 | 自动跑，点击跳栏；草叶外圈 +1、金芯再 +1；碰栏继续 | `3×安全越栏 + 外圈次数 + 内圈次数`；20 栏、10 草 | 固定运行到 45 秒；无生命值或 LIFE_OUT |
| 赶羊入圈 | 摇杆移动犬，绕后跟随驱赶，适时吠叫，把 8 羊赶进圈 | `6×入圈数`；全齐另加 `clamp(floor((1200-finalTick)/30),0,32)` | 8 羊全齐或 45 秒到点 |

准确坐标、整数运算、运动、碰撞、窗口、固定赛道、输入上限和黄金日志只按 02 与唯一 JSON 实现。本 PRD 不复制成另一份可漂移的参数表。赶羊 1200 tick 是时间奖励的 40 秒归零点，玩法上限仍为 1350 tick / 45 秒。叠高高与跨栏离散动作使用按下边沿，长按及键盘自动 repeat 不自动形成每帧新动作。

入账统一条件：已核验、合法自然结束、被接受玩法操作至少一次、完整提交按时且过程合法。全部满足才得 20 + 表现；否则 0。菜单/开始点击、不合法连点不能代替有效操作。客户端预测分只作局内反馈，不直接写余额。

荣誉累计等于三槽当前有效贡献；余额等于有符号积分流水。例：73、40、65 累计 178；兑换 100 后余额 78、荣誉仍 178；73 分局作废后余额 5、荣誉 105；替换场获 50 后荣誉 155、余额 55。退款按原成交价，消费/退款不影响荣誉。每槽多条历史尝试只保留一个当前贡献，任何异常补偿也不能突破 300。

无有效参与成绩者显示“尚未取得有效成绩”，不以 0 分并列第一。同分采用竞赛名次 1、2、2、4，不拿上传时间、完成时间、最高单局或隐藏小数决胜。三局有效时总分 60–300 仅有 241 个整数位置，不能保证人人唯一名次。榜单默认只荣誉，实物由积分价格与库存决定。

| O07 数据导出 `/admin/exports` | 参与、局次、账本、订单、库存、匿名试玩数据及审计导出 | 范围和权限确认、导出中/失败、敏感字段脱敏；保留期限由主办方配置 |

手工输入核销凭证只是扫码的等价入口，不绕开权限、时限、限领和库存。异常复核由上述管理流程承接，本期不新增聊天客服、社交系统或人工即时消息平台。

### 5.3 共用展示要求

加载/空/错误/断网/重试/禁用状态都给出原因和下一步；“重试”复用原业务键。只读查询失败不得暗中重发新订单或新局。菜单与 HUD 不穿透为游戏动作；正式返回需明确放弃。静音状态下成功、失败、精准、入圈和等待核验都可理解。低帧可以减少动画，不能改逻辑速度、碰撞或时钟。字体与安全区适配不得遮住跨栏前方或羊圈入口。

## 6. 生命周期与操作边界

### 6.1 活动生命周期

| 状态 | 开放内容 | 转换与约束 |
|---|---|---|
| CHECK_IN | 绑定、教程、练习、资源预检 | 发布关口通过后主办方开放 PLAYING |
| PLAYING | 普通正式预约、练习，以及有效原槽授权补场；共享开关可停新开局 | 到挑战截止自动 DRAINING；可提前关闭；仍在 PLAYING 时可审计延长 |
| DRAINING | 已准入局、按时提交、核验、复核；有效指定原槽授权可补场 | 等每局真实截止和全部关口，不向全员重开；补场有独立准入截止 |
| REDEEMING | 已封榜；新兑礼、旧单取消/核销 | 新单与核销还受领取截止限制；可结束进入 CLOSED |
| CLOSED | 只读结果；合法既有订单在领取截止前可核销/取消 | 正式活动终态；无新挑战、补场或新兑换 |

普通 start 仅在 PLAYING 且严格早于普通挑战截止时成立，并跳过所有为补场授权保留的槽；仍有其他普通空槽则使用它，没有则拒绝普通开局。带 grant 的补场 start 可在未封榜 PLAYING / DRAINING 执行，必须入口开关为 true、授权归属与原槽匹配且严格早于 grant.admission_deadline；授权可跨普通挑战截止，在 DRAINING 继续使用。授权取消或到期表示该次补偿已处置，不把原槽重新变成普通可用。补场不增加槽数，仍只替换原贡献。普通剩余槽与补场入口分别展示，避免把保留槽误显示为可直接普通开始。

`accepting_new_sessions=false` 只停止新的正式/练习准入，不改变阶段或任一已预约局时轴。紧急中止是另一项有审计的操作，先暂停入口、再选受影响原局作废并为原槽创建保留授权；不能把系统中止当玩家放弃，也不能一键让所有人获得第四次有效分。

### 6.2 局次、资格与客户端状态分离

服务端局次记录至少区分 SCHEDULED、RUNNING、AWAITING_SUBMISSION、VERIFYING、REVIEW、SETTLED、ABANDONED、TIMED_OUT、VOIDED；正常终局原因和奖励资格另存。零操作正常结束可以 SETTLED 且奖励资格为否；过程判无效保留核验结论与原因，不能与正常玩法失误混淆。具体 enum 及字段由 contracts 一次定义，不让各页面自行发明状态。

待同步、请求结果未知、日志无法恢复、只读控制端等是客户端展示状态，不是擅自修改服务端局状态的理由。已经封存后只查询结果，不能继续操作或重组另一份过程。

### 6.3 精确时间边界

| 字段/操作 | 规则 |
|---|---|
| created_at | 预约事务锁齐、作出准入决定时的服务端时刻 |
| play_started_at | created_at + 3000 ms |
| play_ends_at | play_started_at + 45000 ms |
| submit_deadline | play_started_at + 60000 ms；提前自然结束也不改变 |
| 普通/补场 start | 严格早于相应准入截止；等于截止拒绝 |
| 首次完整 finish | play_started_at ≤ received_at ≤ submit_deadline；完整 body 同步入口采样 |
| 核销/新订单 | 锁齐后的业务校验时刻严格早于 claim_closes_at；等号拒绝 |
| 到期取消 | 当前时刻 ≥ claim_closes_at |

250 ms 仅用于未来输入及 end_tick 合理性检查，不增加局长或提交宽限。准时完整 body 因数据库排队跨截止仍按实际 received_at 处理。首版单 Fastify API 实例 + 有限 worker_threads，完整受理屏障和 COMMIT 前同步复扫按 07 实现；不得未经验证扩成多 API。

## 7. 礼品、钱包与现场交付

新兑换在同一事务完成资格、余额、库存、限领检查，扣原价积分、预留库存并创建 RESERVED 订单。RESERVED 与 CLAIMED 都占一人一件名额。取消只针对未领取订单，原价退款并释放预留与名额；同一订单的取消、到期和核销只能有一个终态。核销不再扣一次积分。

库存恒等式：总量 = 可用 + 预留 + 已领取，各项非负；总量下调不能低于预留+已领取。价格修改只影响新单，旧单使用快照。成绩问题导致资格未决或余额不足时，冻结新订单与旧待领凭证；已领取的保留记录和待处理差额，不自动退款/返库或清零负余额。

领取截止必填真实未来时间，并向参与者公开；首次公布后可以有审计地延长，不悄悄缩短。网络无法确认核销是否成功时先暂停实物交付并查原记录；确需纸质应急时仅一个指定登记点，不允许多台各自离线发放。

若主办方承诺有效完成三局的低分者也有礼，基础档价格需 ≤60 且有足够该档库存或明确补领安排。总礼品数够人数不代表低分者可达标。积分发行上限 300N 不是现金预算；采购预算按真实 `Σ(库存×采购单价)`，物流包装另列。荣誉榜不自动赋予抢礼优先权。
