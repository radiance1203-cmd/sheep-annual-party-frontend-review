# F03/F04/F11 repair target regression

Run from the repository root using the existing Node/tsx/Playwright installation:

```powershell
$env:CASES=''
node --import tsx output/repair-20261027/audit/after/target-regression.mts green-candidate-valid
```

`CASES` may contain a regular expression such as `F11` to limit cases. `AUDIT_URL` may point to another local frontend server. Each run writes its own named directory. Preserve existing runs; use a fresh name when rerunning a candidate.

All API requests are intercepted. GET responses use the existing schema-checked fixture factory. Non-GET API requests are refused inside the browser and cause the target assertion to fail. Official runtime tests restore an isolated fixture session from a complete valid tick-zero input prefix, then read the actual IndexedDB log generated by GamePage/game-core. They do not reserve a real slot or submit a real result.

Preparation checks require an actual canvas, positive successfully decoded image dimensions, all current manifest-required atlas image requests, a nonuniform canvas screenshot, disabled start while decode is held, stable core tick zero, no session requests, 404/retry recovery, and preview after practice reset. The decoder wrapper only delays completion in the explicit gate case. Canvas pixel variation checks provide a blank-scene guard, not artistic acceptance.

Tutorial checks require the real teaching canvas, the same manifest asset classes, no old tutorial hero request, changing rendered object states and no session request. Teaching image variants still require visual review.

Input checks include held movement across bark, diagonal and per-key release, opposing directions, repeat, eight directions, focused Space/Enter/pointer exactly once for all three games, blur, visibility hiding, dialog and input focus isolation. Blur/visibility events are synthesized browser events; the form control is injected only in the audit page. These tests do not substitute for physical keyboards/touchscreen/phone testing.

F12 additionally waits for the real App `/me` polling interval, returns an isolated 503 and asserts the original formal canvas remains mounted and its original log tick continues without a new start/finish.
